Subagent (what we have)

  • A helper inside Claude Code, while we build
  • A Markdown file: .claude/agents/*.md
  • Main Claude hands it a job; it reports back
  • Runs on your Claude subscription
  • Examples: test-writer, block-reviewer

Agent (first one built in M4 Step 3)

  • Part of the app: Python that calls Claude itself (here via claude -p)
  • Lives in src/ as a block, with a SPEC and tests
  • Our scripts check what it writes (e.g. sentence_validator), and failures go back with the reasons
  • Runs as a batch job you start, or live during the quiz with a fallback and an off switch; tokens are logged on every call
  • Examples: answer_writer (built, batch), judge (built, live, one call per unknown answer), sentence_writer (built, batch + live, one word at a time during play); all via claude -p under the subscription (ADR 0005, 0007); later, sentence-translation grading

7. How strict is each safety net?

The M1 lesson: if it really matters, make it a hard stop. Only GitHub settings stop everyone, you included.

Hard stop
  • deny rule + hook on .env
  • GitHub secret push protection
  • protected main (PR + green CI, admins too)
  • reviewer has no edit tools
  • uv sync --locked in CI
  • "Still the right thing?" filled in on every PR (CI check)

Can't be skipped by accident.

Automatic
  • ruff format after every edit
  • CI runs on every push and PR
  • contract test in every block
  • .gitignore keeps .env out of git
  • Claude review comments on every PR
  • no test can call the real Claude (conftest)
  • live sentence checks: every sentence Claude writes during play goes through the script checks before it's shown or saved

Happens without anyone remembering.

Guidance
  • CLAUDE.md rules (checks before "done", use /new-block)
  • script vs agent rule (ADR 0002)
  • test-writer "only write in tests/"
  • update this build map after every step
  • /code-review before every PR

Claude follows it; nothing enforces it.

Habit
  • thinking hard about "Still the right thing?" (CI only checks it was answered)
  • docs updated after every step
  • small steps, stop for your go-ahead (agent work: plan the 4-PR split first)
  • judge eval before changing its prompt or model

Part of how we work.
