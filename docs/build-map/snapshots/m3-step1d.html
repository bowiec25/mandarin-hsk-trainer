Subagent (what we have)

  • A helper inside Claude Code, while we build
  • A Markdown file: .claude/agents/*.md
  • Main Claude hands it a job; it reports back
  • Runs on your Claude subscription
  • Examples: test-writer, block-reviewer

Agent (M4, not built yet)

  • Part of the app: Python that calls the Claude API itself
  • Lives in src/ as a block, with a SPEC and tests
  • Uses our script functions as tools (e.g. check_vocab_level)
  • Runs without Claude Code; costs API tokens, so it's logged
  • Example: sentence_writer

7. How strict is each safety net?

The M1 lesson: if it really matters, make it a hard stop. Only GitHub settings stop everyone, you included.

Hard stop
  • deny rule + hook on .env
  • GitHub secret push protection
  • protected main (PR + green CI, admins too)
  • reviewer has no edit tools
  • uv sync --locked in CI

Can't be skipped by accident.

Automatic
  • ruff format after every edit
  • CI runs on every push and PR
  • contract test in every block
  • .gitignore keeps .env out of git
  • Claude review comments on every PR

Happens without anyone remembering.

Guidance
  • CLAUDE.md rules (checks before "done", use /new-block)
  • script vs agent rule (ADR 0002)
  • test-writer "only write in tests/"
  • update this build map after every step
  • /code-review before every PR

Claude follows it; nothing enforces it.

Habit
  • "Still the right thing?" before each plan
  • docs updated after every step
  • small steps, stop for your go-ahead

Part of how we work.
